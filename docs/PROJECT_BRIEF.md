# 角色
你是一名资深全栈工程师，擅长 ASP.NET Core、Vue 3、MySQL、Docker 部署，熟悉医疗健康类产品的安全与合规要求。

# 项目
项目名（暂定）：心灯。Slogan：在情绪的夜里，留一盏灯。
定位：抑郁情绪科普与自助支持网站，可落地部署。

功能模块：
1. 科普内容：文章、分类、来源标注、审核发布
2. 自评量表：PHQ-9、GAD-7、SDS，配置化量表引擎，计分与分级
3. 情绪日记：每日心情打分、标签、文字、趋势图、提醒
4. 社区：部署 Discourse，通过 DiscourseConnect 与本站账号 SSO
5. 咨询预约：咨询师档案、可约时段、预约与取消、通知
6. AI 陪伴：调用大模型 API，带危机识别与安全话术
7. 危机干预：贯穿全站
8. 后台管理：用户、内容、量表、预约、预警工单、审核

# Skill 使用规则
当前可用且与本项目相关的 skill 只有下表这些，其余 skill 与本项目无关，不要调用。

| 环节 | 使用的 skill | 要求 |
|---|---|---|
| 每个阶段的页面验收 | control-browser | 启动本地服务后，打开 localhost 实际访问并截图，确认无报错再宣布完成 |
| 关键流程黑盒测试 | web-gui-tester | 阶段 1 起必须使用：作答 PHQ-9，第 9 题选 1 分以上，确认弹出求助页；之后每阶段的验收项都用它复测 |
| 架构图、ER 图、危机干预流程图 | visualize | 阶段 0 输出 |
| 隐私政策、用户协议、免责声明的文档版 | docx / pdf | 阶段 6 生成草稿，注明"需人工法务审阅" |
| 前端静态演示预览链接 | site-deploy | 仅部署前端静态演示，且只能使用 mock 数据；禁止包含任何真实用户数据、密钥或真实后端地址 |

没有专用 skill 的方面（.NET 后端、数据库、前端实现、加密、安全、AI 提示词、Docker 部署、代码审查）：
直接用自带的代码与终端能力完成，不要假装调用 skill。每个步骤结束前，按下表逐项自查，并把结果写进步骤总结。

| 方面 | 自查要点 |
|---|---|
| 数据库与迁移 | 有主键和必要索引；utf8mb4；迁移脚本按序号排列且可重复执行；敏感字段长度能容纳密文 |
| 后端接口 | 默认需鉴权，匿名接口已显式标注；入参经 FluentValidation 校验；统一返回体；异常不泄露堆栈 |
| 量表与危机逻辑 | 计分、分级有单元测试；第 9 题 ≥1 分必定触发预警；触发后有工单记录 |
| 加密与隐私 | 密钥不在代码与仓库里；日记与答案落库为密文；日志无明文；有注销、导出、删除能力 |
| 前端页面 | 加载、空状态、错误状态都已处理；危机入口在主要页面可见；移动端可用 |
| AI 陪伴 | 危机命中时不调用模型；系统提示词含"非医生 / 非治疗师"声明；有限流与审计日志 |
| 部署 | docker compose 能一键启动；环境变量有模板；无硬编码密码 |
| 文档 | README 写清如何运行；待确认事项都记在 /docs/TODO.md |

# 阶段计划
阶段 0：规划（不写业务代码）
- 0.1 写 CONVENTIONS.md 与 PROGRESS.md。
- 0.2 输出 ER 设计与 SQL 建表脚本（用户、量表、作答记录、日记、文章、预警工单、咨询师、预约等），并用 visualize 画 ER 图。
- 0.3 输出接口清单、危机干预流程图、风险清单。

阶段 1：骨架 + 量表 + 危机提示（最小可用版本）
- 1.1 后端解决方案骨架、统一返回体、全局异常中间件、Serilog、OpenAPI + Scalar。
- 1.2 迁移工具与量表相关表。
- 1.3 量表引擎：JSON 配置格式、计分与分级接口，内置 PHQ-9、GAD-7、SDS。
- 1.4 危机触发服务与预警工单。
- 1.5 /web 前端骨架：首页、量表列表、作答页、结果页、危机求助页。
- 验收：作答 PHQ-9 且第 9 题选 1 分以上，必须弹出求助页并生成预警工单（用 web-gui-tester 实测）。

阶段 2：账号 + 情绪日记 + 后台
- 注册登录（短信 / 邮件先用 mock）、JWT、刷新令牌。
- 日记增删改查（AES-GCM 加密）、趋势图、提醒设置。
- /admin 骨架：登录、用户、预警工单、量表管理。
- 验收：数据库中日记正文为密文；后台可处理预警工单。

阶段 3：科普内容 + 社区
- 文章模块：分类、来源、审核流、发布。
- Discourse 的 Docker 配置；用 .NET 实现 DiscourseConnect SSO（HMAC-SHA256 签名校验）；社区发帖关键词预警回调。
- 验收：未审核文章前台不可见；社区发帖命中关键词生成预警工单。

阶段 4：咨询预约
- 咨询师档案（含资质字段与审核状态）、可预约时段、预约与取消、通知；支付仅预留接口。
- 验收：同一时段并发预约不超卖（写并发测试）。

阶段 5：AI 陪伴
- AI 网关：系统提示词、会话限流、危机识别前置拦截、日志脱敏与审计。
- 前端聊天界面，固定显示"非医生 / 非治疗师"提示。
- 验收：输入自伤相关语句时不调用模型，直接返回固定安全话术与求助入口。

阶段 6：部署与合规收尾
- docker-compose.yml、Nginx 配置、.env.example、备份与恢复脚本。
- 隐私政策、用户协议、免责声明草稿（docx / pdf）；合规待办清单（备案、个人信息保护、咨询服务与生成式 AI 相关要求），全部标注"需人工确认"。
- 全量安全自查与代码审查报告；用 site-deploy 仅部署 mock 数据的前端演示。
